# 大屏默写竞技场 Spec

## Why
当前大屏看板是「被动监控」模式，老师开启默写后只能看到学生进度，缺乏紧张感和竞技氛围。需要改造为「同场竞技大屏」——所有学生同时默写相同的单词、相同顺序，大屏上固定 8 个卡位实时展示每个人的输入状态，配合倒计时紧迫感和宠物反应，营造课堂上的紧张默写氛围。

## What Changes
- 服务端：老师开启默写时生成固定单词序列（Fisher-Yates 洗牌），所有学生拿到相同题目和顺序
- 学生端：检测到老师开启默写后，使用服务端下发的统一题目序列，而非本地随机抽取
- 大屏 UI 重新设计：固定 4×2 网格（最多 8 人），暗黑竞技场主题，紧迫感特效
- 倒计时时钟：最后 60 秒进入「红色警报」状态，数字脉冲 + 背景呼吸灯
- 宠物状态联动：答对时宠物开心、答错时宠物沮丧、完成时宠物庆祝
- 排名实时浮动：得分变化时卡片顺位平滑移动
- 自动全屏：老师点击「开始默写」后自动进入浏览器全屏
- 最多 8 人上限：超出 8 人时只显示前 8 名（按得分排名）

## Impact
- Affected specs: 大屏实时看板
- Affected code: `server.js` (live session 序列生成 + API), `public/app.js` (学生端获取序列 + 大屏渲染), `public/style.css` (大屏竞技场样式), `public/index.html` (大屏 HTML 结构)

## ADDED Requirements
### Requirement: 统一题目序列
系统 SHALL 在老师开启默写时生成一份固定的单词序列（基于选定题库随机抽取 count 条，Fisher-Yates 洗牌），存入 live session，所有参与学生通过 API 获取同一份序列。

#### Scenario: 老师开启默写
- **WHEN** 老师选择题库、数量、时长并点击「开始默写」
- **THEN** 服务端生成 `{bankId, count}` 对应的固定题目序列并存入 `liveBoards[cls.id].sequence`
- **AND** 学生端调用 `/api/live/practice` 时返回该序列

#### Scenario: 学生获取统一题目
- **WHEN** 学生在老师开启默写后进入「今日练习」并点击「开始练习」
- **THEN** 系统使用 `/api/live/practice` 返回的统一序列而非本地随机抽取
- **AND** 所有学生看到的题目顺序完全一致

### Requirement: 大屏竞技场 4×2 固定网格
系统 SHALL 在大屏模式下以 4 列 × 2 行固定网格展示最多 8 名学生的默写状态卡片。

#### Scenario: 学生不足 8 人
- **WHEN** 在线学生少于 8 人
- **THEN** 空余卡位显示为「虚位以待」占位卡片（半透明、虚线边框、龙蛋图标）

#### Scenario: 学生超过 8 人
- **WHEN** 在线学生超过 8 人
- **THEN** 只显示得分最高的前 8 名学生
- **AND** 顶部统计栏显示「当前在线 N 人 · 大屏展示前 8 名」

### Requirement: 倒计时紧迫感
系统 SHALL 在倒计时最后 60 秒触发「红色警报」模式，增强紧迫感。

#### Scenario: 最后 60 秒警报
- **WHEN** 剩余时间 ≤ 60 秒且 > 0 秒
- **THEN** 时钟数字变为红色脉冲动画
- **AND** 大屏背景出现呼吸式红色光晕
- **AND** 所有未完成卡片边框变为暖色警告色

#### Scenario: 时间到
- **WHEN** 倒计时归零
- **THEN** 时钟显示「00:00」并冻结
- **AND** 所有卡片停止更新
- **AND** 顶部弹出「时间到！」横幅

### Requirement: 宠物状态联动
系统 SHALL 根据学生的实时默写状态切换宠物 SVG 的表情/动作。

#### Scenario: 答对当前词
- **WHEN** 学生正确输入并进入下一词
- **THEN** 宠物区域短暂显示「开心」特效（缩放弹跳 + 星星粒子）

#### Scenario: 答错当前词
- **WHEN** 学生答错、进入 locked 状态
- **THEN** 宠物区域短暂显示「沮丧」特效（抖动 + 灰色滤镜）

#### Scenario: 全部完成
- **WHEN** 学生完成全部题目
- **THEN** 宠物区域显示「庆祝」特效（旋转 + 彩色纸屑）

### Requirement: 自动全屏
系统 SHALL 在老师点击「开始默写」后自动请求浏览器全屏。

#### Scenario: 开始默写自动全屏
- **WHEN** 老师点击「开始默写」且请求成功
- **THEN** 自动调用 `#view-live` 的 `requestFullscreen()`
- **AND** 如果浏览器不支持全屏则静默降级

### Requirement: 排名实时浮动
系统 SHALL 在得分变化导致排名变更时，以平滑动画交换卡片位置。

#### Scenario: 排名变化
- **WHEN** 某学生的得分排名与上一轮轮询结果不同
- **THEN** 卡片通过 CSS transition 平移到新位置（而非瞬间跳变）

## MODIFIED Requirements
### Requirement: 大屏实时看板渲染
原 `renderLiveGrid()` 改为渲染固定 4×2 竞技场布局，包含：
- 竞技场顶部横幅：标题「🏟️ 默写竞技场」+ 题库名称 + 倒计时
- 4×2 卡片网格（固定 8 格，不足补占位，超出取前 8）
- 每个卡片包含：排名徽章、宠物 SVG（含状态动画）、姓名、宠物名、得分、进度条、实时输入字符、正确/错误统计
- 底部状态栏：在线人数、已完成人数、最高分、平均分

**原有行为**：auto-fill 自适应网格，不限人数，无紧迫感设计
**新行为**：固定 4×2 竞技场，最多 8 人，含紧迫感与竞技氛围

### Requirement: 学生端默写入口
学生端检测到老师开启默写后：
- 原有：题库锁定、显示倒计时横幅、自行随机抽取题目
- 新行为：题库锁定、显示倒计时横幅、**使用服务端统一题目序列**
